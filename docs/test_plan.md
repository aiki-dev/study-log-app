# テスト計画書（Study Log App）

## 1. 目的

Study Log App（学習時間記録アプリ）が、仕様どおりに正しく動くかを確認する。

特に以下を確認する。

- 入力フォームから正しく登録できるか
- サーバー側のバリデーションが正しく動くか
- 正しい入力のときだけCSVに保存されるか
- 成功・エラーのメッセージが正しく表示されるか
- 保存済みの学習記録を検索できるか

本テストは、ポートフォリオとして
「仕様作成 → テスト設計 → テスト実行 → 不具合報告」
の流れを再現することを目的とする。

---

## 2. テスト対象（SUT）

- Webアプリ：Study Log App（Flask）

確認する機能

- 入力フォーム（POST送信）
- 入力チェック（必須、型、範囲、日付の妥当性など）
- CSVへの保存
- 成功メッセージ・エラーメッセージ表示
- 科目検索
- 日付範囲検索
- 開始日が終了日より後の場合のエラーメッセージ表示
- 条件なしでの全件表示
- 検索結果0件時のメッセージ表示

## 4. テスト範囲

### 4.1 実施する内容

- 入力チェック（必須）

  - 日付が空欄の場合、エラーになるか
  - 科目が空欄の場合、エラーになるか
  - 学習時間が空欄の場合、エラーになるか
  - 複数項目が空欄の場合、エラーになるか

- 入力チェック（日付）

  - 日付がYYYY-MM-DD形式か
  - 存在しない日付（例：2026-02-30）がエラーになるか

- 入力チェック（学習時間）

  - 学習時間が整数か（小数・負数・文字は不可）
  - 学習時間が1〜1440の範囲か

- 正常入力時

  - 成功メッセージが表示される
  - CSVに1件追加される

- 異常入力時

  - エラーメッセージが表示される
  - 成功メッセージが表示されない
  - CSVに保存されない

- 画面表示の確認

  - 成功時／失敗時で表示メッセージが仕様どおりか確認する

- 検索機能の確認

  - 科目を入力して検索した場合、入力した科目を含む記録が表示されるか
  - 開始日と終了日を入力して検索した場合、指定した日付範囲の記録が表示されるか
  - 開始日が終了日より後の場合、エラーメッセージが表示されるか
  - 検索条件を入力しない場合、保存済みの学習記録が全件表示されるか
  - 一致しない条件で検索した場合、「該当する記録がありません。」が表示されるか

## 5. テスト観点

- 正常系：正しい入力で保存できるか
- 異常系：誤った入力でエラーになるか
- 境界値：1・1440などの端の値が正しく処理されるか
- 表示確認：メッセージが正しく出るか
- 保存確認：CSVに正しく追記されるか（既存データが消えないことも含む）
- 検索確認：条件に応じて正しい記録が表示されるか

---

## 6. テスト設計技法

- 同値分割

  - OKパターンとNGパターンに分けてテストする

- 境界値分析

  - 学習時間の境界値を確認する

    - 0（NG）
    - 1（OK）
    - 1440（OK）
    - 1441（NG）

- 空欄の組み合わせも必要に応じて確認する

---

## 7. テスト実行方法

- ブラウザで手動操作して確認する
- CSVファイルを直接確認する
- pytestで代表的な正常系・異常系・境界値テストを実施する
- 不具合が出た場合は bug_report.md に記録する

### CSV確認方法

- 成功時：1行増えていること
- 成功時：追加された行の内容が入力値と一致していること
- 成功時：既存の行が消えていないこと（追記になっていること）
- 失敗時：行数が変わっていないこと
